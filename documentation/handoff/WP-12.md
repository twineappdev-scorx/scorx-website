# WP-12: Cookie consent banner (decision D18)

## Note for the legal reviewer

The Meta Pixel (ID 1528173681585526) now loads only after a visitor clicks Accept. Before a choice, after Decline, after dismissing with Escape, or if browser storage is unavailable, no request goes to `connect.facebook.net` or `facebook.com`, and no Pixel cookie is set. The `<noscript>` tracking image could not be gated, so it was removed from every page. `privacy.html` and `terms.html` had only their Pixel script block changed; their text is untouched (the legal draft owns it). Page copy that says the site does not track visitors, or that describes the Pixel, should be checked against this behaviour.

## How consent works

- `js/consent.js` is the only place the Pixel loader exists. Every page has one line: `<script src="/js/consent.js" defer></script>` (relative paths `../js/` and `../../js/` on `match/` and `sports/*/`, which use relative asset links). `/card/` adds `data-pixel-auto-config="false"` so it keeps its existing `fbq('set','autoConfig',false,...)` call before `init`.
- Choice is stored in `localStorage["scorx_consent"]` as `{v:1, analytics:true|false, ts}`. All access is in try/catch. If storage fails the visitor counts as not consented and the banner still shows.
- `window.scorxConsent = { get(), set(bool), open() }`. A `scorx:consent` event (`detail.analytics`) fires on load and on each change.
- Before consent `window.fbq` is a no-op stub (queues and sends nothing), so inline `fbq(...)` calls cannot throw. On consent the stub is removed and the standard loader runs with the same `init` and `PageView` calls as before. No page made any other `fbq('track', ...)` calls.
- Switching to Decline after Accept in the same page view restores the stub and deletes `_fbp` and `_fbc` cookies. Fully effective after reload, when nothing loads.
- `js/card/analytics.js` calls `fbq` only when `scorxConsent.get()` is true.
- No other third-party tracker exists (searched for gtag, GTM, TikTok, LinkedIn, Hotjar, Clarity, Plausible, PostHog in HTML/JS). The `posthog` line in `analytics.js` is a guarded no-op on the web (the object is never defined).

## Banner

One approach covers all pages: `consent.js` injects the markup and a `<link>` to `css/consent.css` (derived from the script's own URL, so it works at any depth). There is no `_includes/consent-banner.html`, because an include would miss the hard-coded pages and duplicate the markup. The styles are self-contained (own variables using the token colours, light and dark via `prefers-color-scheme` and `[data-theme]`), so pages that only load `style.css` or `tokens.css` both work.

- Bottom sheet, `role="dialog"`, `aria-modal="false"`, `aria-label="Cookie consent"`. No focus trap, page stays scrollable and clickable.
- Text: "We'd like to use cookies to measure how people find ScorX. Nothing is collected unless you say yes." plus a Privacy policy link.
- Accept and Decline are the same size, weight and colour. Escape closes the banner for that page view only: nothing is stored and nothing loads.
- Contrast (computed): light 14:1 text and 14:1 button; dark 11:1 text and 7:1 button; links 6:1 or better.
- Footer "Cookie settings" link (`data-cookie-settings`, href `privacy.html` as a no-JS fallback) is in `_includes/site-footer.html` and the footers of `match/index.html` and `sports/*/index.html` (8 pages). `/card/` has no footer.

## Test results (Playwright, Chromium, deviceScaleFactor 1; Meta endpoints mocked so requests are observable)

- Fresh context, index, train, sports/afl/, card/, match/: banner shown, 0 requests to `connect.facebook.net` or `facebook.com`.
- Escape: nothing stored, nothing loaded.
- Decline, reload all five pages: 0 requests, no banner.
- Accept: `fbevents.js` loads, calls are `init` then `track PageView`, PageView beacon sent. Reload: loads without banner. `/card/` sends `set autoConfig` first.
- Footer "Cookie settings" on train (accepted to declined): reload loads nothing. Link also opens the banner on sports/afl/ and match/.
- localStorage blocked: banner shows, nothing loads, no errors.
- No console errors in any state (39 checks pass).
- `jekyll build` succeeds; `python3 documentation/handoff/check_links.py`: 2360 internal links in 57 pages, 0 broken.
- `grep` for `connect.facebook.net` or `facebook.com/tr` in HTML: no matches (only in `js/consent.js`).
